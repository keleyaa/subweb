实施作战图

三域分离的小步提交计划

目标是把现状的 Legacy 双域基线，按 PRD 逐步推进到 Three-domain mode，同时保留兼容窗，不让一次改动把旧行为和新行为一起打碎。

主约束先传播配置，再拆网关，再切 MyUrls，最后补测试。
兼容边界Legacy 允许 SHORT_DOMAIN=APP_DOMAIN；Three-domain 必须显式提供且三域不同。
最小回滚每步都可回退到前一版文件，不跨步合并语义。
Legacy compatibility mode Three-domain mode Read-only audit

执行顺序

按最少文件、最少语义跳跃来做

优先复用现有模式和模板：先把 SHORT_DOMAIN 和 SHORT_URL 贯通，再把短链路由从 APP 里拆到独立 SHORT host，最后把测试改成分模式断言。每一步都同时写清验证命令和失败回滚。

Step 1 配置传播

把短链域名作为一等输入贯穿部署与运行时

改动文件

  • scripts/configure.sh
  • compose.yaml
  • scripts/lib/config.sh
  • start.sh
  • scripts/render-gateway-config.sh

代码契约

  • 新增 SHORT_DOMAIN 解析、校验、写入。
  • SHORT_URL 固定语义为 https://SHORT_DOMAIN/short-api。
  • Legacy 未显式提供 SHORT_DOMAIN 时回退到 APP_DOMAIN。
  • Three-domain 模式缺少 --short-domain 必须失败，不得静默回退。

验证命令

  • tests/deploy/configureScript.spec.js
  • tests/runtime/config.spec.js
  • tests/runtime/startScript.spec.js
  • tests/gateway/configRendering.spec.js

失败回滚

  • 若 SHORT_URL 仍指向 APP 域，回退 scripts/configure.sh 和 compose.yaml。
  • 若三域模式未强制校验 SHORT_DOMAIN，回退渲染器改动，先保留 Legacy 路径。
Step 2 网关拆分

把 SHORT host 从 APP 路由里独立出来，只保留迁移兼容入口

改动文件

  • nginx/snippets/short-routes.conf.template 新增
  • nginx/templates/http.conf.template
  • nginx/templates/direct-tls.conf.template
  • nginx/snippets/app-routes.conf.template

代码契约

  • SHORT host 只承载 /healthz、/short-api/short、单段短码跳转和 404 catch-all。
  • APP 只保留旧短链兼容入口，不再承担正式三域职责。
  • HTTP 与 direct-tls 都要新增 @@SHORT_DOMAIN@@ server block。

验证命令

  • tests/gateway/routingContract.spec.js
  • tests/gateway/configRendering.spec.js
  • scripts/verify-integrated-stack.sh

失败回滚

  • 若 SHORT host 还能返回前端或访问 /sub，回退新模板，只保留 APP 兼容路由。
  • 若三 SAN 或 unknown-host 421 断言不稳，先停在 Legacy 路由分离，不推进三域验收。
Step 3 MyUrls 切域

让新建短链返回 SHORT 域，而不是继续锚定 APP

改动文件

  • compose.yaml
  • tests/deploy/composeStack.spec.js
  • tests/integration/gatewayStack.spec.js
  • scripts/verify-integrated-stack.sh

代码契约

  • Three-domain mode 时 MYURLS_DOMAIN 必须是 SHORT_DOMAIN。
  • Legacy 仍允许 MYURLS_DOMAIN=APP_DOMAIN。
  • 新建短链的 ShortUrl 必须按模式分支：Legacy 仍可落 APP，Three-domain 必须落 SHORT。

验证命令

  • tests/deploy/composeStack.spec.js
  • tests/integration/gatewayStack.spec.js
  • scripts/verify-redis-operations.sh

失败回滚

  • 若 ShortUrl 仍落到 APP 域，回退 compose.yaml 的 MyUrls 域名变更。
  • 若 Legacy 行为被误伤，保留旧分支并把三域检查收回到测试层。
Step 4 本机三入口

把 local 工具链扩成 app / api / short 三入口

改动文件

  • scripts/local/lib/common.sh
  • scripts/local/render-config.mjs
  • scripts/local/start.sh
  • scripts/local/status.sh
  • scripts/local/stop.sh
  • scripts/verify-local-source.sh

代码契约

  • 新增 LOCAL_SHORT_PORT=18083，只在 Three-domain mode 作为真实短链入口。
  • 端口唯一性、占用检测、状态和停止链路都要覆盖 short。
  • 本机渲染的 shortUrl 不能再默认落到 LOCAL_APP_PORT/short-api。

验证命令

  • tests/local/configDerivation.spec.js
  • tests/local/ports.spec.js
  • tests/local/start.spec.js
  • tests/local/status.spec.js
  • tests/local/stop.spec.js

失败回滚

  • 若 short 端口引入连锁失败，先退回 LOCAL_SHORT_PORT 相关渲染和守护，保留原双入口启动链。
  • 若状态/停止脚本与运行记录不一致，优先恢复旧端口集合，再重做三入口生命周期。
Step 5 测试分层

把真实集成测试拆成 Legacy 回归和 Three-domain 验收两层

改动文件

  • tests/deploy/configureScript.spec.js
  • tests/deploy/composeStack.spec.js
  • tests/gateway/configRendering.spec.js
  • tests/gateway/routingContract.spec.js
  • tests/integration/gatewayStack.spec.js
  • tests/local/*.spec.js
  • tests/runtime/*.spec.js

代码契约

  • Legacy：确认旧行为不坏，不要求三域隔离。
  • Three-domain：确认 SHORT_URL、MYURLS_DOMAIN、SAN、路由隔离和本机端口都落在正确域上。
  • 不要把 Legacy 断言硬改成三域断言，避免抹掉 PRD 允许的兼容窗。

验证命令

  • 按文件逐个跑对应 spec
  • 再跑完整集成脚本：scripts/verify-integrated-stack.sh
  • 最后补一轮本机/部署回归

失败回滚

  • 如果某个 spec 无法同时表达两种模式，就拆成两个 case，不要把断言写成条件地狱。
  • 如果三域测试不稳定，先保留 Legacy 套件通过，再逐步把三域 case 收紧。
PRD 与现状的直接冲突

当前实现仍是 Legacy 双域模型：SHORT_URL 语义、MyUrls 域名、网关 server block、direct-tls SAN、本机端口集合都还没进入 Three-domain mode。也就是说，不能只改一个默认值就宣称完成；必须把配置传播、路由拆分、MyUrls 域名、证书和测试一起切过去。

建议的提交节奏
  1. 先做配置传播和渲染器，保证新旧模式都能从同一入口导出正确值。
  2. 再做网关拆分和 MyUrls 切域，保证新建短链真正落到 SHORT 域。
  3. 最后把测试分层收紧，验证 Legacy 不坏、Three-domain 真隔离。
