# 界面设计规范

## 目标

Subweb 是单页订阅转换工具。界面应将注意力留给输入、配置和转换结果，不增加营销区块、数据卡片或额外操作路径。

## 品牌与结构

- 顶部左侧固定显示 `Subconverter Web`，用于页面内导航识别。
- 顶部右侧只放明暗主题切换；GitHub 链接不在顶部重复出现。
- 页面保持单列：标题与简短说明、一个转换工作区、仓库页脚，顺序不可改变。
- 页脚显示已验证的 GitHub 仓库链接，格式为 `GitHub 项目 · <owner>/<repo>`；没有有效配置时隐藏链接，不渲染空白占位。

## 聚焦玻璃材质

采用“聚焦”方向：转换工作区是页面唯一较大的主材质面。

- 导航、主工作区和页脚分别代表结构层、工作层、来源层，最多三层材质。
- 主工作区使用半透明背景、细亮边、低对比阴影和 `backdrop-filter`；不在工作区内部继续叠加玻璃卡片。
- 输入框、选择器、结果框使用更高不透明度的内层表面，优先保证文本、边界和焦点状态清晰。
- 主工作区圆角为 `28px`；导航和页脚为 `18px` 至 `20px`；输入与按钮为 `12px`。二级界面不使用过大的圆角。
- 不添加漂浮光球、插画、装饰性图标行或营销式大标题。背景只允许低对比环境光，以区分透明材质，不可干扰表单阅读。

## 主题

- 未设置偏好时跟随系统主题；用户切换后保存明确的 `light` 或 `dark` 偏好。
- 主题状态写入 `<html data-theme>`，并同步根级 `color-scheme`，使原生控件、滚动条、弹窗与页面一致。
- 浅色主题使用偏冷的银白画布、珍珠白主材质和深蓝操作色。
- 深色主题使用烟灰蓝黑画布、深色半透明主材质和高对比蓝色操作色；不可仅对浅色主题简单反色。
- 主题切换为原生图标按钮，最小点击区域 `44px`，并提供动态 `aria-label` 和 `aria-pressed`。

## 反馈与无障碍

- “转换订阅”和“生成短链”各自使用单一主按钮：首次点击完成生成并自动复制，成功后按钮切换为对应的“复制”状态，不再并列额外复制按钮。
- 转换结果置于工作区下方；短链仅在配置有效服务时显示。任何失败都保留当前输入，并给出可操作的错误提示。
- 主题、按压、悬停和展开仅使用 `160ms` 至 `240ms` 的颜色、阴影、透明度或极小缩放反馈。
- `prefers-reduced-motion: reduce` 下移除位移和缩放，仅保留短促透明度或颜色变化。
- `prefers-reduced-transparency: reduce` 下关闭模糊并提高材料不透明度。
- `prefers-contrast: more` 下提高边框、文字和 `3px` 焦点环对比度。
- 正文和输入文本在两种主题下满足正常文本对比度要求；主操作按钮必须保留清晰可读的前景色。
